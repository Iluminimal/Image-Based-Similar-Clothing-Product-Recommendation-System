# Загваруудын харьцуулалт ба YOLO detector-ийн нөлөө

Дипломын ажлын туршилтын хэсэг. Бүх тоог Apple M1 (8 GB) дээр PyTorch / MPS ашиглан, Kaggle "Fashion
Product Images" датасетийн цэвэрлэсэн 41,885 бүтээгдэхүүнээр хэмжсэн. Үр дүн `docs/perf/models.*`,
`docs/perf/detection.json`-д бий; дахин гаргах заавар доор.

## 1. Харьцуулсан загварууд

| Загвар | Төрөл | Embedding | Зургийн хэсгийн параметр | Revision |
| --- | --- | --- | --- | --- |
| **FashionCLIP** (`patrickjohncyh/fashion-clip`) | CLIP ViT-B/32, fashion-д fine-tune | 512 | 87.5 M | `7e3ba62c` (production) |
| **Marqo-FashionSigLIP** (`Marqo/marqo-fashionSigLIP`) | SigLIP ViT-B/16, fashion-д fine-tune | 768 | 92.9 M | `c56244cc` |
| **ResNet-50** (torchvision `IMAGENET1K_V2`) | ImageNet-ээр сургасан CNN, fashion-ийн талаар мэдлэггүй | 2048 | 23.5 M | weights-ийн hash `11ad3fa6` |

ResNet-50 нь fine-tune хийсэн загварууд ImageNet-ийн ерөнхий CNN-ээс хэр илүү болохыг харуулах
baseline. Marqo-FashionSigLIP нь FashionCLIP-ийн хамгийн ойрын өрсөлдөгч.

## 2. Арга зүй

- **Ижил оролт.** Загвар бүр каталогийн зургийн ЯГ ИЖИЛ 224x224 uint8 массивыг авна. Үүнийг ingestion-тэй
  адил `to_clip_array` бэлтгэнэ: зургийг дөрвөлжин болтол нь цагаан дэвсгэр нэмнэ (`pad`). Загварууд зөвхөн
  normalize хийхдээ өөр өөрийн mean/std-ийг ашиглана. Тиймээс гарах ялгаа preprocessing-оос биш,
  загвараас үүснэ.
- **Query.** Каталогийн бүтээгдэхүүн бүр (41,885) нэг query болно. Хайлт нь exact cosine (ANN индексгүй).
  Query болсон бүтээгдэхүүнийг өөрийг нь үр дүнд тооцохгүй.
- **Relevant.** Үр дүнгийн датасет дахь label query-ийнхтэй таарвал relevant гэж үзнэ: `category` = ижил
  article type; `colour` = article type + үндсэн өнгө; `strict` = article type + өнгө + хүйс. Label таарах нь
  жинхэнэ "төстэй"-г зөвхөн ойролцоогоор хэмждэг (ижил төрлийн хоёр цамц огт өөр харагдаж болно). Тиймээс
  colour, strict-ийн тоо бага гардаг.
- **Хэмжүүр.** mAP@K, P@K, recall@K, hit rate, nDCG@K (K = 5, 10, 20; `ml/metrics.py`). Хүснэгтэнд K = 10.
- **Статистик.** Query бүр дээр тухайн загвар, FashionCLIP хоёрын AP@10-ийн зөрүүг авч, paired bootstrap-ээр
  (2000 дахин түүвэрлэж) 95%-ийн итгэлийн завсар тооцсон. Завсар 0-г агуулаагүй бол `*` тэмдэглэв.
- **Хурд.** Encode хийх хугацааг MPS дээр batch 1, 32-оор, загвар ачаалсны дараа хэмжсэн
  (preprocessing-ийн хугацаа ороогүй).
- **Baseline.** Үр дүнг санамсаргүй эрэмбэлсэн тохиолдол.

## 3. Загваруудын үр дүн (41,885 бүтээгдэхүүн, K = 10)

| Загвар | mAP category | mAP colour | mAP strict | P@10 category | nDCG@10 category | ms/зураг (batch 32) | ms (batch 1) |
| --- | --- | --- | --- | --- | --- | --- | --- |
| FashionCLIP | 0.830 | **0.281** | **0.256** | 0.866 | 0.875 | **7.6** | **20.7** |
| Marqo-FashionSigLIP | **0.842***| 0.268* | 0.247* | **0.875** | **0.885** | 27.0 | 44.3 |
| ResNet-50 | 0.750* | 0.183* | 0.162* | 0.799 | 0.811 | 11.4 | 29.3 |
| Санамсаргүй | 0.021 | 0.002 | 0.001 | 0.057 | 0.057 | | |

mAP@10-ийн FashionCLIP-ээс зөрүү (95% завсар):

| | category | colour | strict |
| --- | --- | --- | --- |
| Marqo-FashionSigLIP | +0.012 (+0.011 … +0.013) | −0.013 (−0.015 … −0.012) | −0.009 (−0.011 … −0.008) |
| ResNet-50 | −0.080 (−0.082 … −0.077) | −0.098 (−0.100 … −0.096) | −0.094 (−0.096 … −0.092) |

Каталогийн embedding-ийн хэмжээ (fp32): FashionCLIP 86 MB, Marqo 129 MB, ResNet-50 343 MB.

### Дүгнэлт

1. **Fashion-д fine-tune хийсэн загвар ImageNet-ийн CNN-ээс тод давуу.** Category дээр +0.08, харин
   өнгө, хүйсээр нарийсгахад +0.09-0.10: ResNet-50 өнгөний ялгааг сул таньдаг. (ResNet-50-ийн
   embedding нь 4 дахин том, тиймээс индекс, санах ойд ч илүү өртөгтэй.)
2. **FashionCLIP, Marqo-FashionSigLIP бараг тэнцүү боловч давуу тал нь өөр.** Marqo article type-ийг
   бага зэрэг илүү сайн таньдаг (+0.012), харин өнгө, хүйс нэмэхэд FashionCLIP илүү (+0.013, +0.009).
   Эдгээр зөрүү статистикийн хувьд тодорхой ч практикт бага ач холбогдолтой (query бүрд 0.01 орчим).
3. **Хурдны зөрүү их.** Marqo нь FashionCLIP-ээс ~3.5 дахин удаан (27 vs 7.6 мс/зураг, нэг зураг
   дээр 44 vs 21 мс) бөгөөд embedding нь 1.5 дахин том. Marqo зөвхөн category дээр, тэр ч бага зэрэг
   давуу бөгөөд энэ нь нэмэлт зардлаа нөхөхгүй тул **FashionCLIP-ийг production-д хэвээр үлдээсэн**.
4. Өнгө, хүйс дээрх бага зөрүү нь label-ийн чанар (датасетийн өнгө ихэвчлэн хоёрдмол утгатай) болон
   хоёр загварын сургалтын өгөгдлөөс шалтгаалсан байж болзошгүй. Сургалтын өгөгдөл энэ датасеттай
   давхцаж байгаа эсэхийг шалгаагүй.

## 4. YOLO detector-ийн нөлөө

Датасетийн зураг бүр ганц бүтээгдэхүүнтэй студийн зураг бөгөөд bbox label байхгүй. Тиймээс detector-ийг
**синтетик collage**-аар хэмжсэн (`scripts/evaluate_detection.py`): каталогийн 2-3 бүтээгдэхүүнийг (цамц,
өмд, гутал, цүнхнээс) санамсаргүй цайвар дэвсгэр дээр нэг эгнээнд наана. Ингэснээр бүтээгдэхүүн бүрийн
байрлал (ground truth) урьдаас мэдэгдэнэ. Нийт 300 collage, 748 зорилтот бүтээгдэхүүн.

Collage доторх *нэг бүтээгдэхүүнийг* хайхад ижил label-тэй бараа хэр сайн олдсон (mAP@10):

| Арга | category | colour | strict | P@10 category | hit@10 category |
| --- | --- | --- | --- | --- | --- |
| **whole**: бүтэн collage-аас нэг vector гаргах (YOLO-гүй) | 0.207 | 0.062 | 0.049 | 0.276 | 0.539 |
| **yolo**: тухайн бүтээгдэхүүнийг агуулсан detection-г embed | **0.771** | **0.268** | **0.242** | 0.810 | 0.925 |
| oracle: бүтээгдэхүүний өөрийн зураг (дээд хязгаар) | 0.839 | 0.294 | 0.268 | 0.878 | 0.991 |

YOLO нь category mAP-ийг **3.7 дахин** нэмэгдүүлж, oracle-ийн 92%-д хүрсэн.

Detector-ийн өөрийнх нь үзүүлэлт:

| | |
| --- | --- |
| Бүтээгдэхүүн илэрсэн (ямар ч ангилалтай) | 87.8% |
| Илэрсэн, ангилал нь зөв | 74.5% |
| Төрлөөр: цамц / өмд / цүнх / **гутал** | 100% / 100% / 88.3% / **64.8%** |
| Нэг зурагт олсон хэсэг (дундаж) | 3.26 (collage-д 2-3 бүтээгдэхүүн) |
| Ямар ч бүтээгдэхүүнд хамаарахгүй хайрцаг | 0 |
| Detection-ий хугацаа p50 / p95 (MPS) | 64 / 127 мс |

Илрээгүй бүтээгдэхүүний хувьд (12%) "yolo" мөрөнд бүтэн collage-ийн vector ашигласан тул тэдгээр нь
"whole"-тэй ижил оноо авсан. Жинхэнэ апп дээр илрээгүй зүйлийг сонгох боломжгүй: хэрэглэгч зөвхөн
илэрсэн хэсгээс сонгоно. Хамгийн сул нь **гутал**: 35% нь илрээгүй. Шалтгааныг шалгаагүй; гутлын зураг
жижиг, эсвэл confidence-ийн босго (0.25) өндөр байсан байж болно.

### Хязгаарлалт

- Collage бол студийн зургуудыг цагаан эсвэл цайвар дэвсгэр дээр эвлүүлсэн зураг. Жинхэнэ гэрэл зураг (хүн
  өмссөн, давхарласан хувцас, гэрэл сүүдэр, бүдэг) үүнээс хэцүү. Тиймээс энэ туршилт detector-ийн *нөлөөг*
  л хэмждэг, бодит ашиглалтын нарийвчлалыг хэмждэггүй.
- Collage дахь бүтээгдэхүүнүүд ижил хэмжээтэй, нэг эгнээнд байрласан, хоорондоо давхцдаггүй.
- "yolo" мөр нь тухайн бүтээгдэхүүний ангилалд тохирох detection-ийг шууд сонгодог (хэрэглэгч товшсон
  мэт). Жинхэнэ UI-д хэрэглэгч хэсгээ өөрөө сонгоно, анхдагч нь хамгийн тод хэсэг.

## 5. Ганц бүтээгдэхүүнтэй зураг дээрх алдагдал

Каталогоос санамсаргүй сонгосон, ганц бүтээгдэхүүнтэй 1200 зургаар шалгав (хэрэглэгч нэг зүйлийн зураг
оруулсан тохиолдол). YOLO-ийн олсон хамгийн тод хэсгийг embed хийхийг бүтэн зургийг embed хийхтэй
харьцуулбал:

| mAP@10 | category | colour | strict |
| --- | --- | --- | --- |
| Бүтэн зураг (YOLO-гүй) | 0.825 | 0.279 | 0.254 |
| YOLO-ийн 1-р хэсэг | 0.809 | 0.268 | 0.246 |

Төрлөөр (category): Accessories 0.890 -> 0.883, Apparel 0.830 -> 0.808, Footwear 0.731 -> 0.720. Detector
1200 зургийн 90%-д ямар нэг хэсэг олсон.

Шалтгаан нь detector-ийг сургасан өгөгдөл (Fashionpedia: хүн өмссөн, гудамж, подиумын зураг) каталогийн
ойроос авсан студийн зургаас ялгаатайд бий. Цөөн жишээг (6 цэнхэр Casual Shoes, 3 цаг, 3 цүнх, 3 өндөр өсгийт)
нүдээр шалгахад **гутал, цаг, цүнх, өндөр өсгийтийг хувцас гэж буруу таньж байв**: 6 Casual Shoes-ийн 6
нь `shorts`, цагнууд `skirt` эсвэл `top`, цүнхнүүд `pants`, `top`, `vest`, өндөр өсгийт `top`, `cardigan`,
`sweater`. Collage-д гутлын илрэлт (65%) бага байсан нь үүнтэй холбоотой байж болох ч шалгаагүй. Хайрцаг
ихэвчлэн тухайн зүйлийг багтаадаг тул crop хийхэд хайлт бага зэрэг л муудна. Харин label нь найдваргүй.
Тиймээс UI дээр label-ийг барааны нэр шиг харуулах нь буруу (гутал "Шорт" гэж гарна).

Боломжит сайжруулалтууд (хэмжээгүй): (a) зөвхөн нэг хэсэг олдсон бол бүтэн зургаар хайх (ганц бүтээгдэхүүнтэй
зургийн алдагдлыг арилгана); (b) бүтэн зургийг үргэлж сүүлийн хэсэг болгож нэмэх; (c) label-ийг UI-д харуулахаа
болих; (d) catalogue маягийн зураг дээр detector-ийг fine-tune хийх.

## 6. API-ийн хугацаа (YOLO-той)

`make latency DEVICE=mps`, жинхэнэ апп, FashionCLIP + YOLOv8m, 200 хүсэлт (YOLO-гүй хэмжилт `docs/search-api.md`):

| | p50 / p95 | Зорилт |
| --- | --- | --- |
| Зургаар хайх, эх зураг (1800x2400) | 129 / 161 мс | p95 < 400 мс ✔ |
| Зургаар хайх, утасны 1280 px | 119 / 155 мс | p95 < 400 мс ✔ |
| Холимог хайлт | 122 / 145 мс | p95 < 400 мс ✔ |
| `POST /search/garments`, 3 бүтээгдэхүүний collage (дунджаар 3.5 хэсэг) | 122 / 143 мс | p95 < 400 мс ✔ |
| 4 зэрэгцээ клиент (утасны зураг) | 398 / 508 мс, 9.5 req/s | |

Detector нэмснээр нэг хүсэлт ~60-65 мс удааширсан (өмнө p50 ~54 мс). Embedder, detector хоёр нэг GPU-г
хуваалцдаг (`ml/gpu.py`) тул зэрэг ирсэн хүсэлтүүд ээлжлэн боловсруулагдана. Анхны хэмжилтээр p95 нэг
удаа 339 мс гарсан (warm-up-ийн нөлөө), давтан хэмжихэд 161 мс байв.

## 7. Үр дүнг дахин гаргах

```bash
cd apps/api
# 1. Загваруудын харьцуулалт (анх удаа ~1 цаг: embedding-ийг docs/perf/embeddings/-д cache хийнэ; --limit 2000 бол жижиг туршилт)
uv run --group bench python ../../scripts/benchmark_models.py --out ../../docs/perf/models.json
#    -> models.json, models.md (хүснэгт), models.tex (дипломд оруулах)
# 2. YOLO-ийн нөлөө (FashionCLIP-ийн кэшийг дахин ашиглана)
uv run python ../../scripts/evaluate_detection.py --collages 300 --out ../../docs/perf/detection.json
# 3. Бодит API-ийн хугацаа
DATASET_DIR=~/Datasets/fashion make latency DEVICE=mps
```

`make benchmark`, `make evaluate-detection` нь эдгээрийн товчлол. Загваруудын weights-ийг тодорхой revision-д
тогтоосон тул өөр машин дээр ч ижил embedding гарна.
